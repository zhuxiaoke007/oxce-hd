# P9 修复报告 — 弹出窗口不遮挡 HD 文字（下拉菜单背景穿透）(2026-08-25)

## 现象

基地层「购买/雇佣」「制造」「卖掉」等界面，点开 ComboBox 下拉菜单（如
「全部物品」）时，下拉菜单背景与列表中的背景文字（如「士兵」「空中游侠」）
叠加显示，文字穿透弹出菜单，难以分辨。

## 根因

渲染管线的遮挡不一致，分两层：

- **帧缓冲（320×200 位图层）**：下拉菜单的 `Window` 背景绘制在帧缓冲里，
  正常覆盖其下方的列表文字。✓
- **HD 文字覆盖层（显示分辨率层）**：仅保存字形墨迹（无背景），且永远
  合成在帧缓冲**之上**。每个帧循环里，下方的 TextList 先绘图并把字形
  盖进覆盖层；随后菜单 `Window` 只画帧缓冲，**不清覆盖层**；最后合成时，
  之前盖入的底层文字字形浮在菜单背景之上——这就是「穿透」。

伴随现象：菜单展开与收起都受影响（收起后菜单区域字形残留消失是因为
覆盖层每帧清空，由下一帧底层文字重新盖入）。

## 修复（Window::blit 覆写 + Screen::clearTextOverlayRect）

| 文件 | 改动 |
|------|------|
| `Engine/Screen.h/.cpp` | 新增 `clearTextOverlayRect(bx,by,bw,bh)`：按真实内容缩放（与 P8 修复同款分数缩放，floor/ceil 外扩）把窗口矩形内的覆盖层墨迹统一清零（写索引 0=透明）；内部自检 `_hdOverlayActive`/`hdFonts`/非 OpenGL |
| `Interface/Window.h/.cpp` | 新增 `blit` 覆写：窗口可见时，先清覆盖层矩形再 `Surface::blit` 绘制背景 |

顺序保证：State::blit 按 z 序（添加序）逐表面绘制——底层列表先盖字形、
菜单窗口随后擦除并画背景、菜单自己的条目文字最后盖入 → 合成结果：
菜单遮挡底层文字、菜单内容正常显示。窗口内容一律在窗口之后绘制，无关
顺序问题。

## 遗留说明

- 半透明/动画窗口（popup 动画中）会外扩擦除，属瞬时边缘误差，可接受。
- 未对 TextButton、Image 等其他不透明度组件做擦除（无已知问题案例），
  如需同样处理可复用 `clearTextOverlayRect`。
